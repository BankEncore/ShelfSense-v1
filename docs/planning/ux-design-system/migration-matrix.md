# UX design system — migration matrix

Status: **Working tracker** (UDS-0 inventory; update as UDS slices ship)

Values:

- **legacy** — pre–Warm Parchment / pre–action-semantics presentation
- **partial** — at least one accepted token or primitive is present, but one or more action-semantic, component-state, responsive, accessibility, or workflow gates in [the rollout contract](program-plan.md#objective-migration-states) is incomplete or failing; inherited colors alone never qualify for conforming
- **conforming** — every objective requirement in the rollout contract passes (including, for UDS-2/UDS-3 reference surfaces, the [accessibility and ergonomic test matrix](accessibility-ergonomic-test-matrix.md)); the evidence link records commit/PR, baseline observation or screenshot, required viewports, manual workflow result, and accessibility/domain/visual reviewers
- **locked** — intentionally governed by a separate presentation contract; do not inherit screen primitives

## How to use this inventory

Each row names the template or selector that owns the contract, not merely a conceptual screen. “Validation” is the minimum check after migration; it supplements, rather than replaces, the full UDS manual gate and [accessibility-ergonomic-test-matrix.md](accessibility-ergonomic-test-matrix.md) where applicable. Interaction changes are not implied by a visual migration. In particular, UDS-1 must preserve Turbo boundaries, native-dialog focus restoration, Register keyboard/scanner behavior, and print output. Slice change allowlists and token rollback are defined in [program-plan.md](program-plan.md#implementation-rollout-contract).

Risk shorthand: **L** theme-only with broad regression coverage; **M** shared primitive or several consumers; **H** behavior-, density-, focus-, or print-sensitive.

## Legacy alias retirement register

Aliases remain behaviorally stable while listed here. A slice may introduce a new semantic helper/class beside an alias, but must not silently change the alias to a different intent. Status is updated in the same PR as usage changes. Pair with [warm-parchment.md](warm-parchment.md) Phase 2.2 migration aliases and [button-action-semantics.md](button-action-semantics.md) deprecation sequence.

| Legacy alias | Current status | Migration target | Condition for removal |
|---|---|---|---|
| `--color-background` | legacy, live | `--color-bg-canvas` (Warm Parchment) | All `var(--color-background)` consumers are migrated; no occurrences remain outside the temporary alias declaration; all shell viewport/manual gates pass; token rollback window has closed |
| `--color-surface` | legacy, live | `--color-bg-surface` / elevated tokens as required | Every consumer selects the correct canvas/surface/raised/overlay semantic token; opaque dialog and print-preview checks pass; only the alias declaration remains |
| `--color-text` | legacy, live | `--color-text-primary` | All uses migrate and ordinary-text AA contrast passes on every allowed surface/background |
| `--color-text-muted` | legacy, live | `--color-text-secondary` | All uses migrate and AA contrast is measured for small helper, table-header, and metadata text |
| `--color-action` | legacy, live | brand / focus / link tokens by state | Links, focus rings, buttons, and selected states no longer share this catch-all alias; hover/active/focus/disabled checks and non-color cues pass |
| `--color-accent` | legacy, live | brand soft or explicit semantic family by meaning | No action intent depends on plum/accent alone and repository search finds no consumers outside the alias declaration |
| `--color-warning` | legacy, live | warning family tokens | Warning badges, flashes, and review stages use explicit semantic tokens with AA contrast and non-color labels |
| `--color-border` | legacy, live | `--color-border-subtle` / `--color-border-strong` by role | All consumers choose a documented border role and tables, inputs, dialogs, and disabled controls remain distinguishable |
| `--color-danger` | legacy, live | danger family tokens | Error text, destructive triggers, final dialog actions, and focus states use explicit roles; destructive workflow and contrast gates pass |
| `.button-secondary` | legacy compatibility alias | `ActionButtonHelper` outline/neutral | Repository search finds no rendered or generated use; helper tests cover its replacement; admin/ops/POS manual gates pass |
| `.button-danger` | legacy compatibility alias | danger outline trigger or solid final via helper | Repository search finds no rendered or generated use; page trigger versus final review semantics are verified; consequential workflow tests pass unchanged |
| `.btn--secondary` | legacy, live | outline + neutral (+ size) via helper | Every call site has an explicit intent (not inferred from old styling), repository search finds no use, and all three review disciplines approve reference surfaces |
| `.btn--danger` without a style class | legacy, live | danger-outline trigger or danger-solid final, selected explicitly | Every call site is classified by workflow stage; incomplete shorthand is gone; `btn--danger` remains as the **intent** token paired with a style and size |
| `.btn--ghost` without intent/size | legacy shorthand | `btn--ghost btn--neutral btn--standard` via helper | Incomplete shorthand removed after call sites migrate; retain `btn--ghost` as the canonical **style** class—do not remove merely to rename it |

Removal of a **compatibility alias or incomplete shorthand** means deleting both the alias definition and its compatibility tests in one dedicated cleanup PR after at least one completed downstream slice has exercised the replacement. Dynamic class construction and documentation examples must be included in the repository search. If any condition is unmet, the alias remains `partial` or `legacy, live`; elapsed time is not a removal condition.
